Other Notes
------------------------
1. Look for 'MEADOW.OS REBASE' in the code. These are places NOT fixed. But,
committed out.

2. The first first comment lines in most of our files are now wrong. The top
lines often contains old copyright information, wrong file location and the
wrong date, e.g. '/apps/examples/hcom/tests/hcom_dir_mgmt_tests.c'. No
technical value but, should still be done. We should have a standard format.

3. I added /Meadow.OS/nuttx/include/sys/boardctl.h, to Rebase, mostly
because the new rebase automation tooling indicated it was missing. However,
it doesn't seem to be needed in the build (it build without the file) and
the file only contains one entry: include <sys/boardctl.h>

4. Looks like Meadow/nuttx/include/meadow/'meadow_syscall.h' has been
been renamed 'meadow_syscall_support.h'. Contents are different too.
Legacy Meadow currently has no references to meadow_syscall.h.
This needs to be fixed to match the most current legacy Meadow.

5. The function hcom_nx_upd_diag_fd_inode() in
Meadow.OS/Meadow.OS/hcom_nx/hcom_nx_upd.c is no longer useable with Nuttx 12.
Why? Because it directly accessed internal Nuttx structures that no longer
exist in Nuttx 12. The code is currently commented out and I inserted
a syslog statement as a place holder.

6. The file meadow_client_cert.c probably works but, I prevented the code from
building because it generates a lot of warnings. This is temporary until the
the warnings have been addressed.

7. Meadow.OS/meadow_os/meadow-upd.c:509
warning: implicit declaration of function 'stm32_pwminitialize'
Looked easy enough, until I started to dig. Looks like the Nuttx team
totally rewrote timer support, with different configuration options.
While we use timers for Meadow.OS things, these don't depend on Nuttx
support.

8. Why not remove CONFIG_MEADOW_PWR_MGMT_SUPPORT as a options as it is
always part of Meadow.OS. MEADOW_INCLUDE_CODE_FOR_ROTARY_ENCODER should also
be removed and made permanent? Is it integrated in to Meadow.Core?
